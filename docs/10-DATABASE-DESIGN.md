# 10 — Database Design

## Schema ownership

- **Flyway owns the schema** (`backend/src/main/resources/db/migration`):
  `V1__init.sql`, `V2__seed_categories.sql`, `V3__add_waste_snapshot.sql`,
  `V4__add_refresh_generation.sql`.
- `hibernate.ddl-auto=none` — Hibernate never modifies the schema.
- `flyway.baseline-on-migrate: true`, `baseline-version: 0`.
- No Row-Level Security: authorization is enforced in the Spring service
  layer (ownership checks), per the V1 migration comment.
- Host: Supabase-managed PostgreSQL, connected via
  `DB_URL=jdbc:postgresql://...?sslmode=require` (the `jdbc:` prefix is
  mandatory).

## Tables

### users
| Column | Type | Constraints |
|---|---|---|
| id | uuid | PK (UUID generated by app) |
| email | varchar(320) | NOT NULL, UNIQUE |
| password_hash | varchar(255) | NOT NULL (BCrypt) |
| display_name | varchar(100) | nullable |
| role | user_role enum | NOT NULL, default `USER` |
| created_at | timestamptz | NOT NULL, default now() |
| refresh_generation | bigint | NOT NULL, default 0 (V4) |

### categories
| Column | Type | Constraints |
|---|---|---|
| id | uuid | PK |
| name | varchar(50) | NOT NULL, UNIQUE |
| default_shelf_life_days | integer | NOT NULL, default 3 |
| warning_threshold_days | integer | NOT NULL, default 3 |

Seeded by V2: `grocery` (30/3), `medicine` (365/7), `perishable` (7/1)
(`on conflict (name) do nothing`).

### items
| Column | Type | Constraints |
|---|---|---|
| id | uuid | PK |
| owner_id | uuid | NOT NULL, FK → users ON DELETE CASCADE |
| name | varchar(200) | NOT NULL |
| barcode | varchar(32) | nullable |
| category_id | uuid | NOT NULL, FK → categories |
| quantity | numeric(10,2) | NOT NULL, default 1, CHECK (quantity >= 0) |
| unit | varchar(20) | NOT NULL, default 'unit' |
| purchase_date | date | nullable |
| expiry_date | date | nullable |
| shelf_life_days | integer | nullable |
| notes | text | nullable |
| created_at | timestamptz | NOT NULL, default now() |
| updated_at | timestamptz | NOT NULL, default now() |

Indexes:
- `items_owner_expiry_idx (owner_id, expiry_date)`
- `items_barcode_idx (barcode)`

Trigger: `items_set_updated_at` → `set_updated_at()` sets `updated_at = now()`
on UPDATE.

### waste_log
| Column | Type | Constraints |
|---|---|---|
| id | uuid | PK |
| item_id | uuid | FK → items ON DELETE SET NULL (nullable) |
| user_id | uuid | NOT NULL, FK → users ON DELETE CASCADE |
| item_name | varchar(200) | nullable snapshot (V3) |
| unit | varchar(20) | nullable snapshot (V3) |
| quantity_wasted | numeric(10,2) | NOT NULL, CHECK (quantity_wasted > 0) |
| estimated_cost_lost | numeric(10,2) | nullable, CHECK (estimated_cost_lost >= 0) |
| logged_at | timestamptz | NOT NULL, default now() |

Index: `waste_log_user_idx (user_id, logged_at desc)`.

Snapshot rationale (V3 comment): `markWasted` deletes the item in the same
transaction, so without `item_name`/`unit` the history would be lost.

### notifications
| Column | Type | Constraints |
|---|---|---|
| id | uuid | PK |
| item_id | uuid | FK → items ON DELETE CASCADE |
| user_id | uuid | NOT NULL, FK → users ON DELETE CASCADE |
| type | notification_type enum | NOT NULL (`EXPIRING_SOON` / `EXPIRED`) |
| channel | varchar(20) | NOT NULL, default 'email' |
| sent_at | timestamptz | NOT NULL, default now() |

Indexes:
- `notifications_dedup_idx UNIQUE (item_id, type, date_trunc('day', sent_at, 'UTC'))`
  — database-level idempotency for digest emails.
- `notifications_user_idx (user_id, sent_at desc)`.

### product_cache
| Column | Type | Constraints |
|---|---|---|
| barcode | varchar(32) | PK |
| payload | jsonb | NOT NULL (raw Open Food Facts JSON) |
| fetched_at | timestamptz | NOT NULL, default now() |

## Enums (Postgres `CREATE TYPE`)

- `user_role` = `USER` | `ADMIN`
- `notification_type` = `EXPIRING_SOON` | `EXPIRED`

Java enums are mapped with `@Enumerated(EnumType.STRING)` +
`@JdbcTypeCode(SqlTypes.NAMED_ENUM)` to the Postgres named enums.

## Test database

`backend/src/test/resources/schema-h2.sql` mirrors the entity model on H2
(users, categories, items, waste_log) for integration tests — notably the
pessimistic-locking tests (`MarkWastedConcurrencyTest`). It is test-only and
not part of the runtime.

## Design decisions (verified from migrations)

1. Authorization lives in the app layer, not the database (no RLS).
2. Waste history survives item deletion via snapshots + `ON DELETE SET NULL`.
3. Digest idempotency is enforced at the database level with a unique
   index, so racing job executions cannot double-send.
4. Refresh-token revocation is a simple counter bump, not token storage.
